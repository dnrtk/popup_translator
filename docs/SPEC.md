# ローカル翻訳ツール(DeepLアプリ代替)開発指示書

## 0. このドキュメントについて
- Claude Code への実装指示書。作業開始時にこのファイル全体を読み、**フェーズ1から順に**進めること。
- 各フェーズ開始前に実装計画を提示し、確認を取ってから着手する。
- 「6. 要調査事項」は推測で実装せず、必ず一次情報(モデルカード、tokenizer設定、llama.cppのリリースノート)を確認してから進める。確認結果は `docs/FINDINGS.md` に記録する。

## 1. 目的
DeepL デスクトップアプリの「Ctrl+C+C で選択テキストを翻訳」体験を、**完全ローカル(外部通信なし)**で再現する Windows 常駐アプリを作る。

- 翻訳エンジン: PFN **PLaMo 3 Translate**(GGUF)を llama.cpp の `llama-server` で動かす
- 既定モデル: `pfnet/plamo-3-translate-0.8b`(GGUF Q4_K_M、約0.57GB)
- 他サイズ(2B / 8B / 31B)へ設定から切り替え可能にする

## 2. 技術スタック
| 項目 | 採用 |
|---|---|
| 言語 | Go(最新安定版) |
| UI | Wails(v3 が安定版なら v3。マルチウィンドウ・システムトレイが標準で使えるため。安定していなければ v2 + トレイ実装を検討し、判断理由を FINDINGS.md に記録) |
| フロントエンド | Wails 標準テンプレート(Vanilla TS または Svelte。軽量なもの) |
| 推論 | llama.cpp `llama-server`(同梱。子プロセスとして起動・管理) |
| 対象OS | **Windows 10/11 を最優先**。Linux(X11)は後回しで、OS依存部分はインターフェースで分離しておく |

## 4. 機能仕様

### 4.1 ホットキー(Ctrl を押したまま C を2連打)
- `SetWindowsHookEx(WH_KEYBOARD_LL)` によるグローバルフックで実装する。
  - `runtime.LockOSThread()` した専用 goroutine で `GetMessage` ループを回す。
  - フックのコールバックは**即座に返す**(重い処理はしない。チャネルに通知して終わり)。
  - **キーは握りつぶさず**、必ず `CallNextHookEx` で後続に渡す(通常のコピーはそのまま動かす)。
- 判定ロジック:
  - 左右どちらかの Ctrl が押されている間だけ、C(VK 0x43)の**押下エッジ**を数える。
  - C を押しっぱなしにしたときのキーリピートは数えない(C の KeyUp を見てから次の押下を受け付ける)。
  - Ctrl を離したらカウントをリセットする。
  - 2回目の押下が1回目から **400ms 以内**(設定値)なら発火する。
  - 他のアプリが合成したキー入力(`LLKHF_INJECTED`)は無視する。
- 発火したら **80ms 待ってから**(設定値)クリップボードを読む。

### 4.2 クリップボード
- `CF_UNICODETEXT` を読む。`OpenClipboard` は他アプリが掴んでいると失敗するので、短い間隔で数回リトライする。
- 空文字や空白だけのときは何もしない。
- 長さの上限(既定 8,000 文字)を超えたら、ポップアップに「長すぎる」と表示する(分割翻訳はフェーズ3)。

### 4.3 言語判定と訳先の決定
- 原文の言語はモデルの自動判定に任せる(`source_lang` は指定しない)。
- アプリ側の判定は「日本語かどうか」の1点だけ:
  - ひらがな(U+3040–309F)、カタカナ(U+30A0–30FF、U+31F0–31FF)、半角カナ(U+FF66–FF9F)を数える。
  - 文字(空白・記号・数字を除く)に占めるかなの割合が **5% 以上**(設定値)なら日本語とみなす。
  - 漢字だけの短文は「日本語ではない」扱いでよい(中国語との誤判定を避けるため)。
- 訳先の既定値: 日本語なら **英語(en)**、それ以外は **日本語(ja)**。
- ポップアップのプルダウンで訳先を変えたら、その場で訳し直す。
- 次回発火時に自動ルールへ戻すか、最後の選択を覚えておくかは設定で切り替える(既定: 自動ルールに戻す)。
- プルダウンには、よく使う言語(ja, en, zh-CN, zh-TW, ko, fr, de, es, …)を上に並べ、その下に対応する全言語を並べる。言語コードの一覧はモデルカードから取得すること。

### 4.4 翻訳
- `llama-server` の `/completion` に、**PFML3 形式のプロンプトを自前で組んで**送る(6章参照)。
- `stream: true` で受け取り、届いたトークンから順にポップアップへ表示する。
- 生成パラメータ: `temperature: 0`(貪欲法)、`cache_prompt: true`。`n_predict` は原文長から上限を決める。停止条件は PFML3 の仕様に従う。
- 翻訳中に新しい発火やプルダウン変更があったら、**実行中のリクエストをキャンセル**してから新しく開始する(`context` でキャンセル)。

### 4.5 ポップアップ
- マウスカーソルの近くに表示する(画面端ではみ出さない位置に調整)。最前面表示で、フォーカスも取る。
- レイアウト: 上段に原文(読み取り専用)、下段に訳文、ヘッダーに「検出: 日本語/その他」と訳先プルダウン。
- 操作:
  - Esc で閉じる
  - 訳文のコピーボタン
  - 原文を編集してから訳し直すボタン(Ctrl+Enter)
- 枠の外をクリックして閉じるかどうかは設定で切り替える(既定: 閉じない)。
- サイズと位置は記憶する。
- 発火してから、まず「翻訳中…」の状態で即座に表示する。ストリーミングが始まるまでの待ち時間を体感させないため。

### 4.6 llama-server 管理
- アプリ起動時に子プロセスとして起動する。主な引数:
  - `-m <model>`
  - `-ngl <0 または 99>`
  - `--host 127.0.0.1 --port <空きポート>`
  - `-c <コンテキスト長、既定 8192>`
- コンソールウィンドウは表示しない(`CREATE_NO_WINDOW`)。
- **Job Object** に入れて、アプリが落ちても llama-server が残らないようにする。
- 起動後は `/health` が ready を返すまでポーリングする。準備中に発火した場合は「モデル読み込み中」と表示する。
- llama-server が異常終了したら1回だけ自動で再起動する。それでも失敗したらトレイ通知を出す。
- llama-server の標準出力・標準エラーはログファイルに保存する。

### 4.7 設定画面
- 開き方: トレイメニューの「設定」。
- 項目:
  - **実行デバイス**: CPU / GPU(`-ngl 0` / `-ngl 99`)。GPU を使う場合はオフロードする層の数も指定可。
  - **モデル**: `models/` 内の `*.gguf` をプルダウンに一覧表示。サイズの目安(0.8B / 2B / 8B / 31B)と、CPU で使えるかの目安も表示する。
  - **モデルのダウンロード**(任意機能、フェーズ3): Hugging Face から選んだ GGUF を取得する。**ユーザーがボタンを押したときだけ**通信する。
  - コンテキスト長、スレッド数(CPU 時)
  - ホットキーの連打間隔(ms)、クリップボードを読むまでの待ち時間(ms)
  - 日本語と判定するかな比率のしきい値
  - 訳先の挙動(自動ルールに戻す / 最後の選択を覚える)
  - 日本語に訳すときの文体(`form`: 常体 / 敬体)。モデルが対応していれば
  - Windows 起動時に自動起動する
- 保存したら、llama-server の再起動が必要な項目(デバイス、モデル、コンテキスト長、スレッド数)だけ再起動する。再起動中であることはトレイとポップアップに表示する。
- 設定ファイルの場所: `%APPDATA%\<アプリ名>\config.json`

### 4.8 その他
- 二重起動を防ぐ(名前付き Mutex)。
- トレイメニュー: 設定 / 一時停止(ホットキー無効化)/ ログフォルダを開く / 終了。

## 5. 非機能要件
- **完全ローカル**: 翻訳処理の中で外部と通信しない。llama-server は `127.0.0.1` だけで待ち受ける。テレメトリは入れない。
- 原文と訳文はログに残さない(デバッグ設定を明示的にオンにした場合を除く)。
- アイドル時の CPU 使用率はほぼ 0 にする(ポーリングは /health の起動時だけ)。

## 6. 要調査事項(実装前に一次情報で確認)
1. **PFML3 のプロンプト形式**: Hugging Face の `pfnet/plamo-3-translate-0.8b` にある tokenizer 設定の chat template と、モデルカードの vLLM Completions 向けの例から、正確なタグ構造、`target_lang` / `source_lang` / `form` などの指定方法、停止トークンを確定させる。`internal/prompt` は、モデルカードの例と完全一致することを確認する**ゴールデンテスト**付きで実装する。
2. **GGUF の配布場所**: 公式の GGUF リポジトリ名とファイル名(サイズ別、量子化別)。
3. **llama.cpp の対応バージョン**: PLaMo 3 のアーキテクチャに対応したリリースを特定し、同梱するバージョンをそれ以降に固定する。
4. **同梱する llama.cpp ビルド**: Vulkan 版を第一候補とする(NVIDIA / AMD / Intel の GPU と `-ngl 0` の CPU 動作を1つのバイナリで賄えるため)。CUDA 版も選べるようにするかは、フェーズ2で速度を比べてから決める。
5. **Wails のバージョン**: v3 の安定度(トレイ、マルチウィンドウ、ウィンドウを最前面にしてフォーカスを奪えるか)。
6. **対応言語コードの一覧**(モデルカードより)。

## 7. フェーズと完了条件

### フェーズ1: MVP
- 6章の 1〜3 を調査して FINDINGS.md に記録する。
- llama-server の起動・停止・ヘルスチェック(パス、モデル、ngl は config.json に手で書く)。
- ホットキー → クリップボード → 言語判定 → ストリーミング翻訳 → ポップアップ表示、の一連の流れ。
- 訳先プルダウンでの訳し直し。
- トレイ常駐(設定画面はまだ不要。終了だけできればよい)。
- **完了条件**:
  - ブラウザ、VS Code、Word のそれぞれで、Ctrl を押したまま C を2連打するとポップアップが出る。
  - 英文 → 日本語、和文 → 英語に訳される。
  - プルダウンで訳先を変えると訳し直される。
  - アプリを強制終了しても llama-server が残らない。
  - 通常の Ctrl+C の動作を妨げない。

### フェーズ2: 設定画面
- 4.7 の項目すべて(モデルのダウンロードを除く)。
- CPU と GPU の切り替え、モデルの切り替え、再起動中の表示。
- 0.8B / 2B の CPU 時・GPU 時の速度を測り(ツールを起動してから最初のトークンが出るまでの時間、トークン/秒)、FINDINGS.md に記録する。
- **完了条件**: 設定画面から CPU⇔GPU、0.8B⇔2B を切り替えられ、アプリを再起動しなくても翻訳が続けられる。

### フェーズ3: 仕上げ
- モデルのダウンロード機能
- 長文の分割翻訳(段落単位)
- Windows 起動時の自動起動、インストーラー(任意)
- Linux(X11)対応の検討

## 8. テスト方針
- 単体テスト:
  - `langdetect`: 和文、英文、中国語(簡体・繁体)、韓国語、漢字だけの短文、混在文
  - `prompt`: ゴールデンテスト
  - `config`: 読み書き、既定値の補完
- ホットキーの判定ロジックは、キーイベントの列を入力して発火するかを返す純粋関数として切り出し、OS に依存しない形でテストする(リピート、Ctrl を離したとき、時間切れ、2回目が遅い場合)。
- llama クライアントはモックサーバーでテストする(ストリーミング、キャンセル、異常終了)。
